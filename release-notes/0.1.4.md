## Fixes and improvements

- Fix empty ERDs after Sync when a browser backup exceeds localStorage quota. Backup failures no longer close the workspace or block existing ERDs.
- Store KeepERD editing data in a local SQLite database shared by browsers and profiles using the same server. No SQLite server or database account setup is required.
- Automatically migrate existing IndexedDB diagrams, tables, relationships, dependencies, custom types, Areas, notes, filters, repository layouts, settings, and legacy backups when each original browser first visits the upgraded app. Browser originals are preserved.
- Select the latest saved complete ERD for the same diagram ID across browsers. Equal timestamps keep the server version; differing older versions are retained as bounded recovery backups. Historical data has no per-table edit timestamp, so selection uses the ERD's saved `updatedAt`.
- Preserve the current Git schema when an old browser Sync revision proves that its structure is obsolete; migrate its layout and notes and retain the complete original as a recovery backup.
- Limit automatic backups to 3 per ERD, 128 total, and 32 MiB of UTF-8 payload. Backup errors are isolated from primary writes; primary-write failures roll back the transaction.
- Preserve the last saved ERD when a new schema cannot be written. Reject stale concurrent saves instead of silently overwriting another browser's work.
- Pin Node.js 26.12.1 for the built-in SQLite runtime. The Homebrew formula supplies the exact runtime privately; it does not replace the user's system Node.

## Upgrade

After the Homebrew formula has been published:

```sh
keeperd stop
brew update
brew upgrade craftdio/keeperd/keeperd
keeperd --version
keeperd start
```

The version command should print `KeepERD 0.1.4`. Open the original address in each browser/profile that holds old data, normally `http://localhost:18777/`. Migration runs automatically; site data must remain available until it completes. A server cannot read an unopened browser/profile's IndexedDB. After migration, browsers read the common server workspace without another schema Sync.

KeepERD continues to keep data on the local machine. SQLite is stored in the existing KeepERD user state directory. JSON sharing remains available for another computer. See the [workspace migration and recovery guide](https://github.com/craftdio/keeperd/blob/v0.1.4/tools/local-erd/SQLITE.md) for timestamp limitations, bounded backup retention, and recovery.
