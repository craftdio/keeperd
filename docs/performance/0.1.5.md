# KeepERD 0.1.5 performance checks

This update promotes three validated optimizations: stable canvas subscriptions, scoped workspace reads/write acknowledgements, and worker-based local branch detail queries. The public repository retains its own release workflow and packaged-runtime checks.

## Reproduction

Use the pinned Node **26.12.1**:

```sh
node tools/local-erd/performance-benchmark.mjs 100 14
node tools/local-erd/performance-benchmark.mjs 300 14
node tools/local-erd/performance-benchmark.mjs 1000 14
node tools/local-erd/branch-performance-benchmark.mjs --worker
```

The fixtures contain synthetic public data only and use temporary SQLite databases/Git repositories. Workspace fixtures have 14 diagrams, ten columns per table, N−1 relationships per diagram, and no Areas or notes. Each read selects one table; each write changes its x coordinate. Results include JSON serialization and exclude HTTP/network time. The scripts also check cross-branch placement and preserve branch-specific field IDs. An entity query still projects its entire target ERD; it does not have constant cost as that ERD grows.

The Git fixture has 102 branches sharing ten distinct feature tips and three worktrees, including one dirty schema. It uses local tracking refs without fetching. Run the synchronous baseline script against the earlier source to compare process counts; the candidate uses `--worker`.

## Source validation observations

Measurements were collected on macOS, Apple M5, ten logical CPUs, 24 GiB RAM, with the pinned Node runtime and a Chromium-based in-app browser. They are observations, not device-independent performance guarantees.

| Scenario                                                                      |             Before |              After |
| ----------------------------------------------------------------------------- | -----------------: | -----------------: |
| 100-table production canvas, sidebar-row renders during two pans              |              1,600 |                  0 |
| Same canvas, table-menu renders                                               |              2,000 |                  0 |
| Same canvas, three observed rAF p95 values (ms)                               | 48.6 / 70.2 / 34.8 | 21.2 / 20.9 / 20.8 |
| One-table read, 14 ERDs × 100 tables, JSON payload bytes                      |          3,071,394 |              1,890 |
| One-table save, same fixture, JSON payload bytes                              |          3,071,424 |                 30 |
| 102-branch query, Git processes                                               |                658 |                 39 |
| 10ms timer scheduled alongside the branch query, observed execution time (ms) |              7,249 |               9.75 |

The browser comparison used a 1280×800 viewport, the sidebar open, sharing closed, overview LOD, zoom 0.189579, and two empty-canvas drags returning to the original viewport. Both versions mounted 100 tables, 497 handles, 99 relationships, and 1,904 canvas DOM descendants. Source and candidate bundles used identical temporary render/rAF instrumentation. Instrumentation is not part of the product. Short manual gestures, browser scheduling, and desktop background load affect frame percentiles; render counts and response sizes are more stable evidence than timing ratios.

The public-repository promotion repeats the native workspace fixture and uses the same runtime algorithms. Regression tests verify actual React Flow selection/viewport behavior and confirm that another HTTP API responds while Git is deliberately blocked. The extracted-release smoke test separately verifies scoped reads, ACK/409 behavior, partial layout apply/restore, browser-module MIME types, and fresh worker results from an archive without `node_modules`.

## Limits

- Branch queries use at most two workers, ten active/queued requests, and a 25-second deadline including queue time. Individual Git subprocesses keep the existing 15-second timeout. A timed-out worker occupies its slot until it actually exits; termination does not guarantee immediate OS subprocess termination.
- Only in-flight requests and commit-pair calculations within one query are shared. Later requests re-read refs and worktree status. Other routes, including repository listing, remote checks, and Sync, still contain synchronous Git work.
- No M1/8GB device run, browser pan benchmark at 300/1,000 tables, long-running editing test, or multi-user latency target was completed. Backend fixture sizes must not be interpreted as equivalent browser/device validation. Real-time collaboration and renderer replacement are outside this update.
